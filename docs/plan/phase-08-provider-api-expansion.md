# Phase 8 — Provider expansion, compatibility inventory, and optional self-update

Status: closed for this release. The provider catalog, supported/pending API inventory, deterministic compatibility evidence, bounded gateway-owned resources, and optional signed Linux self-update are implemented. Live provider certification, remote-database certification, and additional vendor resource families are deferred future work rather than release claims. [Plan index](README.md)

This post-stable expansion phase delivered the bounded items below. ADR-051 closes it for the current release without claiming the deferred work.

## Completion evidence — 2026-09-16

- `./scripts/verify.sh` passed locally: generated-code/OpenAPI drift, formatting, vet, staticcheck, all Go tests, TypeScript, 14 frontend/official-SDK files with 72 tests, race suites, and copied-binary smoke.
- `./scripts/package.sh v0.1.0-checklist` produced Linux amd64/arm64 binaries, archives, and `SHA256SUMS`; both Linux binaries executed `version` under their target Docker platforms.
- A local multi-platform Docker build completed for linux/amd64 and linux/arm64. The image starts the gateway by default.
- `./scripts/compose-e2e.sh` built the production image, completed owner onboarding, created an encrypted paired-store backup in the persistent backup volume, restored it into a clean data volume, verified readiness/login, and preserved the session across restart.
- Startup reconciles interrupted backup jobs and scheduled backups retry after failures. Focused storage, operations, and app tests cover both recovery paths.
- The compatibility and API parity documents state the exact supported subset. Unimplemented media, realtime, hosted-tool, provider-owned resource, semantic-search, live-provider, and remote-database surfaces remain explicit and are not forwarded or claimed.
