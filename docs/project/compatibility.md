Cross-provider generation covers the shared documented subset. Legacy OpenAI Completions stays native to an OpenAI or OpenAI-compatible target because its prompt, log-probability, and candidate semantics are not translated. Anthropic client streaming remains native-target only because input usage is required in the first Anthropic event. Native Anthropic Messages supports bounded ephemeral prompt-cache controls with explicit capability and accounting gates; cache directives are not translated. It also supports one direct JSON or SSE `web_search_20250305` tool with a 1–4 use ceiling, public/upstream `chat` and `web_search`, the built-in `anthropic` preset, and `messages:web_search`; native search blocks, citations, continuation state, SSE frames, and reported calls are preserved without translation or post-dispatch fallback. Gateway-owned Anthropic Message Batches run one to four ordinary Messages locally with creating-key ownership, a 16 MiB submission limit, a 24-hour processing expiry, and ordinary routing/accounting prices; the whole batch and its JSONL results are deleted 29 days after creation. Gateway-owned OpenAI Files store creating-key-owned encrypted `assistants`, `batch`, `fine-tune`, `vision`, `user_data`, and `evals` input for at most 30 days and expose the five stable official SDK operations. Gateway-owned OpenAI Uploads assemble one Batch File from up to 16 encrypted Parts within one hour. Gateway-owned Vector Stores provide atomic create-with-files, file attachments and batches, UTF-8/ASCII, BOM-marked UTF-16, HTML, DOCX, PPTX, and XLSX content extraction, and backend lexical search with separate scope, key ownership, expiry, pagination, aggregate bytes/counts, and shared capacity. Bounded Responses `file_search` runs a private function-tool loop on one native OpenAI/OpenAI-compatible Responses target, searches 1–10 same-key stores, emits official `file_search_call` output, and aggregates usage across provider turns for stateless, stored, and background requests. Gateway-owned OpenAI Responses, Chat Completions, legacy Completions, Embeddings, Moderations, Image Generations, and Image Edits Batches run one to four non-streaming requests locally with creating-key ownership, a 24-hour processing window, ordinary routing/accounting prices, and separate success/error output Files. Legacy Completions reuse the direct strict validator; Embeddings use a fixed vector-space target; Moderations and Images use native routing without fallback. Batch Image Edits accept HTTPS or bounded PNG/JPEG/WebP data URLs and reject provider `file_id` references. Endpoint result bodies stay standard. Aggregate usage is available only when terminal Batch usage is complete; otherwise it is null. They do not claim OpenAI's provider Batch discount, limits, or rate pool. Static token chunking, PDF/legacy Office parsing, semantic Vector Store search, remaining Batch endpoints, and provider-owned Batches remain separate contracts. Responses web search requires an OpenAI-adapter target using the built-in `openai` preset, explicit call/output ceilings, public/upstream capability, and a separate key scope. Search-call cost remains unknown for both web-search contracts, so lowest-cost, free-only, and spend policies reject them before dispatch. Embeddings, moderations, token counting, and Realtime require native capable targets. The Realtime surface is an HTTP/1.1 WebSocket proxy only; OpenAI Live-session resources, WebRTC, SIP, sideband/fork connections, and cross-provider translation remain unsupported. Other hosted tools, opaque reasoning blocks, other cache APIs, and provider-owned conversations are unsupported until explicitly implemented and tested.

The Anthropic contract also supports one basic `web_fetch_20250910` tool with 1–4 uses, an approximate 1–16,384 fetched-text token limit, up to ten allowed or blocked hosts, public/upstream `chat` and `web_fetch`, and `messages:web_fetch`. Native fetched document/PDF blocks, citations, embedded errors, SSE frames, token usage, and reported fetch calls are preserved. Because binary PDFs are outside the text-token bound, token/spend policies, free-only routing, and lowest-cost routing reject fetch requests before dispatch. Web fetch cannot be combined with search, prompt caching, translation, local Message Batches, or post-dispatch fallback.

No paid-provider certification is claimed. CI uses deterministic local providers; live provider results must be added here with date, provider API version, model, and exact operations.
