# 2026-09-16 — Gateway-owned OpenAI Embeddings Batches

ID: ADR-028 · Status: accepted · Source: delegated technical choice extending the user's API-compatibility requirement

**Context.** ADR-024 and ADR-027 established one bounded, gateway-owned OpenAI Batch lifecycle for Responses and Chat Completions. The official Batch API also accepts `/v1/embeddings`, and the gateway already has the fixed-target embedding route, validation, accounting, encrypted Files, and durable Batch machinery needed to execute those items without a second queue.

**Decision.** Extend the existing Batch resource to accept `/v1/embeddings`. Creation requires `batches:manage` plus `embeddings:generate`; every JSONL line must use `POST`, the selected endpoint, one shared public embedding model, and a non-empty embedding input. Supported input forms are a string, an array of strings, one integer token-ID array, or an array of integer token-ID arrays. Multi-input arrays contain at most 2,048 inputs. Optional positive `dimensions`, `encoding_format` of `float` or `base64`, and string `user` pass through to the ordinary embedding path. Workers persist the endpoint, recheck the creating key's current grants, and use the public model's single vector-space target without fallback. Successful output lines preserve the ordinary Embeddings response and public model alias. Reported `prompt_tokens` becomes aggregate Batch input usage, with zero output tokens.

**Consequences.** Responses, Chat Completions, and Embeddings share the encrypted queue, 1–4-item and 16 MiB input bounds, 24-hour processing deadline, 30-day Batch retention, optional 1-hour through 30-day output retention, cancellation, recovery, and separate success/error Files. The gateway still does not claim OpenAI's Batch discount, provider rate pool, or larger limits. Completions, Moderations, image/video Batch endpoints, and provider-owned Batch execution remain separate contracts. This extends ADR-024 and ADR-027 without changing their ownership and lifecycle decisions.
