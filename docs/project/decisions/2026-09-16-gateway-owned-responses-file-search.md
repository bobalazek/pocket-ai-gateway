# 2026-09-16 — Gateway-owned Responses file search

ID: ADR-049 · Status: accepted · Source: user requirement for OpenAI-compatible APIs and backend-owned model metadata/logic, plus delegated Phase 8 compatibility scope

**Context.** The gateway owns encrypted Files and Vector Stores, so their IDs cannot be sent to a provider account. OpenAI Responses `file_search` nevertheless expects the model to choose the query and returns typed `file_search_call` output. Pretending that lexical scores are semantic, searching in the browser, or sending local IDs upstream would break the compatibility, privacy, and backend boundaries.

**Decision.** Accept one bounded `file_search` tool over 1–10 unexpired Vector Stores owned by the calling key. Require `responses:generate`, `responses:file_search`, a positive cumulative output bound, and a native OpenAI or OpenAI-compatible Responses target. Replace the hosted tool with one reserved strict function, execute the existing backend lexical search for the model-selected queries, append only matched text to the stateless provider input, and repeat on the same target for at most four searches. Restore the caller's public tool fields, preserve output order, return official `file_search_call` items, optionally include rich result data for the caller, and aggregate provider usage from every completed turn into one gateway attempt even if a later turn fails. When a turn also emits a caller-owned function call, return both calls rather than forwarding that unresolved call. Support stateless, locally stored, and durable background JSON Responses. Reject streaming, Conversations, previous-response references, prompt templates/cache controls, combined web search, semantic/hybrid ranker selection, translation, and post-dispatch fallback.

**Consequences.** Local Vector Store and File IDs plus attachment attributes stay inside the gateway; only matched text is disclosed to the selected provider. The pinned OpenAI SDK can use the standard tool and output types. Search adds no provider tool fee, but every model turn is reserved and charged at the selected model's versioned token price. Automatic file-citation annotations remain unsupported because the provider only sees a private function result; the gateway does not fabricate character offsets. Embedding-backed ranking can replace the lexical engine only after an explicit embedding model/version/dimension and reindexing contract.
