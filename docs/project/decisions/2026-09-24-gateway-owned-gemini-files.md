# 2026-09-24 — Gateway-owned Gemini Files

ID: ADR-061 · Status: accepted · Source: delegated technical choice for user-requested Gemini API expansion

**Context.** The Google Gen AI SDK uploads to `/upload/v1beta/files` before passing a returned `file.uri` in `generateContent` or `countTokens`. Forwarding that URI upstream would bypass gateway key ownership and depend on a provider-side file with separate credentials. The single Go executable also needs bounded local storage and accounting.

**Decision.** Implement the SDK's resumable start/upload/finalize headers under `/api/gemini/upload/v1beta/files`, with one-hour encrypted upload sessions and key-owned encrypted Files under `/api/gemini/v1beta/files`. A 144-bit random upload URL is a one-hour capability for headerless REST follow-up; a supplied key must match. Identical chunk and finalize retries return their committed result. Accept 1–8 MiB per file, 48-hour logical File expiry, and key-scoped list/get/delete. Expired rows are pruned by scheduled/manual retention and opportunistically on later uploads. Snapshots require the local master key while encrypted Gemini rows exist. Upload URLs use the configured public origin (`POCKET_AI_GATEWAY_PUBLIC_URL` behind a proxy); a directly constructed handler without one falls back to the request scheme and Host. Reject duplicate upload and inference JSON keys; parse parameterized MIME values to the base media type. Support optional official-format `files/{id}` names with uniqueness per key, and generate compliant IDs otherwise. Return opaque `pag-gemini://files/{id}` URIs; expand up to four references with at most 8 MiB of combined source bytes into Gemini inline data before routing and admission. Require `files:manage` for resolution, cap JSON traversal at 64 levels/100,000 values, and enforce the existing 16 MiB expanded request limit. Local file-backed generation, streaming generation, and token counting require a native Gemini target. Reject foreign, missing, expired, mismatched, or nested/unsupported references before dispatch. Shared retained-resource limits include pending sessions and Files. No external runtime or provider-side File is created.

**Consequences.** The pinned Google Gen AI SDK can upload, list, retrieve, delete, generate, and count tokens with same-key local files. API keys need `files:manage` to manage resources; a different key cannot access or resolve them. An upload URI is meaningful only to this gateway. Gemini Interactions file input, provider-side Files and downloads, video-specific asynchronous Files processing, remote URI imports, and files larger than 8 MiB remain unsupported. Files may contain media the selected upstream rejects; no OCR, scanning, or media conversion is implied.

Sources: [Gemini Files guide](https://ai.google.dev/gemini-api/docs/files), [REST Files reference](https://ai.google.dev/api/files), [Google Gen AI SDK Files API](https://googleapis.github.io/js-genai/release_docs/classes/files.Files.html).
