# 2026-09-24 — Versioned hosted web-search call pricing

ID: ADR-060 · Status: accepted · Source: delegated technical choice implementing the owner's pricing request

**Context.** Hosted search returns model-token usage and a bounded count of search calls, but a token-only price understates cost. Unknown per-call fees previously prevented spend caps and historical repricing for every hosted-search attempt.

**Decision.** An immutable price version may include `web_search_usd_per_call`; null means unknown and explicit zero means a verified free call. Standalone native OpenAI Responses and Anthropic Messages search reserve the configured fee for the request's maximum 1–4 calls plus conservatively estimated token cost. Strict spend admission also requires an explicit cache-read rate, bounded output, and the existing bounded input estimate. Settlement charges the provider-reported completed call count plus actual token usage; assessment, ledger, quotas, daily projection, and later repricing use the same combined amount. No vendor rate is hard-coded. The provider response remains native; cost is available through gateway usage endpoints.

**Consequences.** Missing fee or cache-read rate rejects a search request under a strict spend policy and leaves positive-call cost unknown in observational mode. Search with zero reported calls can be priced from tokens alone. Positive cache creation remains unknown until both creation-duration rates are modeled, and prompt-cache requests continue to reject spend policies. Combined Anthropic search and fetch also stays unknown because fetch fees are not modeled; a persisted fetch marker prevents settlement and repricing from charging only search. Migration conservatively marks historical Anthropic search attempts with multiple tools as possibly combined, so an operator may need to reconcile their cost manually. Free-only and lowest-cost search routing remain unsupported until the entire route price contract is comparable.
