# 2026-09-25 — System One decision models

ID: ADR-064 · Status: accepted · Source: owner request to support Jev, Laya, and similar typed-decision models; wire and adapter choices delegated

**Context.** TypeSafe's Jev (hosted, released September 15, 2026) and Convai Innovations' Laya (open-weight, self-hosted through `laya-serve`) are "System One" models: they take unstructured state and typed questions (`noul`, `choice`, `score`) and return calibrated probabilities instead of text. Both use `POST /v1/systemone` with bearer authentication; Jev also lists models at `GET /v1/models`, and Laya does not. Neither fits the OpenAI, Anthropic, or Gemini contracts, so presenting them as chat would mislead clients. ADR-009 makes the path select the client wire format.

**Decision.** Add a fourth protocol root, `/api/systemone/v1`, with `POST /systemone` and `GET /models`. Requests pass through natively without translation, using the shared key authentication, `decisions:generate` scope, `decisions` model capability, routing, limits, pricing, and accounting. Question count is the request's `batch_items`. Provider-reported `usage.input_tokens` and `usage.output_tokens` are recorded; a server that omits usage (Laya) records an estimate, as moderations already do. Errors use the Jev `{"detail":{"error_type","message"}}` shape, and upstream Laya string details are normalized to it. Connections use the existing bearer-authenticated `openai_compatible` adapter with new `typesafe` and `laya` presets that permit only the `systemone` operation, following the Replicate precedent; this avoids rebuilding the foreign-key-referenced connection table.

**Consequences.** TypeSafe's SDK and Pydantic AI can point at `<instance>/api/systemone`. Answers and the provider's versioned `model` field are returned unchanged. Jev's free output is expressed by an operator-configured zero output price. Streaming, cross-format translation, and hosted Cloudflare Workers AI access are unsupported. Live Jev and Laya calls have not been certified; deterministic tests cover forwarding, validation, errors, capability gating, and accounting. A distinct adapter label can be introduced later with a connection-table migration if more System One providers appear.
